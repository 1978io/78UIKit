Tones one vocabulary · _78.tone

The same six names on every component that takes a tone — they are the token names. The aliases (green, red, amber, yellow) are permanent and style identically. This grid is built from _78.tone.names, so it can't drift from the kit.

Categories — labels that are not states

When a label names a kind of thing (a source, a team, a type), a status tone would lie: "Scout" in amber reads as a warning. Six categorical hues, kept clear of success / warn / danger: _78-badge-cat-1 … -cat-6, also on tags, text and the viz primitives. Use them in order; the sixth sits nearest a state.

    Two files, one inline snippet. Nothing to build.

    <head>
  <!-- 1. pre-paint theme (no FOUC) — before any CSS -->
  <script>
  (function(){var p=localStorage.getItem('_78-theme')||'system';
  var t=p==='system'?(matchMedia('(prefers-color-scheme: light)').matches?'light':'dark'):p;
  var r=document.documentElement;r.dataset.theme=t;r.dataset.themePref=p;})();
  </script>

  <!-- 2. the kit -->
  <link rel="stylesheet" href="/78UIKit/css/kit.css">
  <script defer src="/78UIKit/js/_78.js"></script>

  <!-- 3. your own theme overrides, AFTER the kit -->
  <style>:root[data-theme="dark"]{--accent:#7c5cff}</style>
</head>

    Any element with ._78-theme-toggle is wired automatically; otherwise call _78.theme.cycle(). Listen for document.addEventListener('_78:themechange', …) when something canvas-based (Chart.js) has to be redrawn.
