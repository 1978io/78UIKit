The app shell _78.shell

A fixed ._78-topbar, an optional ._78-sidebar that collapses to an icon rail, and a ._78-app-main that makes its own room for both — so page content never has to be re-wrapped. Section headings plus flat items: no nested menus, on purpose.

Try it. The hamburger collapses the sidebar to a rail (hover an icon for its label) and the state survives a reload with no flash — it is restored before the first paint, like the theme. Narrow the window under 768px and the same button opens an off-canvas drawer with a scrim; Escape, the scrim or a nav click closes it.

Notes

  • Two pre-paint snippets, same idea. The theme one sets data-theme; the shell one sets data-sidebar from localStorage['_78-sidebar']. Both live on <html> so the very first paint is already right. _78.shell.PREPAINT holds the exact string.
  • The sidebar is optional. A topbar-only app just leaves out the <aside> and the shell pre-paint snippet — ._78-app-main then only clears the topbar.
  • The rail keeps its labels. They are visually hidden, not removed, so they are still each item's accessible name; the hover/focus tooltip is a decorative aria-hidden chip.
  • Flat items only. Headings group them. No nested or expandable menus — if a section needs sub-pages, they belong in the page, not the nav.
  • Width changes fire _78:railchange — the hook for anything that has to re-measure (a Tabulator table, a Chart.js canvas).
